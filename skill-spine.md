# Shared skill spine

Every website-quality skill uses the same operating shape:

`boundary → contract → selection → profile → execution → evidence → outcome → replay`

The common failure is an invisible dependency: an important relationship whose
owner, conditions, source, proof, or recovery path is hidden from the person it
affects. Review consequential choices from four seats:

- **Client:** Can the owner understand, change, and recover it without one person?
- **Visitor:** Is the real rendered experience correct, usable, accessible, and light enough?
- **Developer:** Is the contract explicit, authoritative, and safe to extend?
- **Time:** Will versions, content, staff changes, and lost context still leave replayable evidence?

Trade-offs name both seats, their benefits and costs, the supporting evidence,
and the reversal path. Developer simplicity does not automatically beat client
control; visitor weight does not automatically beat versioned ownership; speed
does not automatically beat documentation.

## Bones

- **Boundary:** own one discipline and state handoffs without naming private tools.
- **Contract:** record authority, assumptions, conditions, and checked time.
- **Selection:** name the denominator before sampling.
- **Profile:** declare depth and exclusions.
- **Execution:** use ordered, repeatable checks.
- **Evidence:** bind claims to provider, state, method, artifact, and limitations.
- **Outcome:** use `passed`, `findings`, `partial`, `blocked`, or `failed` separately from domain state.
- **Replay:** store enough context to verify fixes and repeat the run.
